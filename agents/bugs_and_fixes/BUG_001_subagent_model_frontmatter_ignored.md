# 🐛 BUG-001: У frontmatter субагента поле `model` может игнорироваться Claude Code

**Дата:** 2026-10-27  
**Компонент:** Claude Code / субагенты (`.claude/agents/`)  
**Статус:** ⚠️ Ожидает фикса у поставщика (обход применён)  
**Источник:** github.com/anthropics/claude-code issue #44385  

---

## 1. Симптом
В файле субагента указан `model: haiku`, но при вызове субагент запускается на модели родительской сессии (opus/sonnet). Поле `model` в YAML-frontmatter не применяется.

## 2. Первопричина (Root Cause)
Баг в Claude Code: документация Agent tool заявляет «если параметр model не передан, используется model из определения агента», но фактически frontmatter-значение игнорируется при вызове без явного параметра.

## 3. Решение (How Fixed)
Обход (workaround):
1. Не полагаться на `model` во frontmatter как на гарантированное.
2. При делегировании основной агент **явно передаёт параметр `model`** в вызове Agent tool (например, `model: "haiku"` для test-writer/docs-keeper).
3. Настройка `CLAUDE_CODE_SUBAGENT_MODEL` как fallback для массового применения.

Затронутые файлы: `.claude/agents/*.md` (поля `model` оставлены как декларация намерения — работают, когда баг исправлен).

## 4. Правило предотвращения
- При настройке субагентов с разной стоимостью моделей проверять фактическую модель в `/tasks` после первого запуска, а не доверять frontmatter вслепую.
- Обновить карточку, когда баг будет исправлен в Claude Code.
