# 📏 Стандарты кодирования: aiogram 3 (пресет aiogram-bot)

> Стек: Python 3.11+ · aiogram 3.x · PostgreSQL (asyncpg/SQLAlchemy 2.0) · Redis · Celery

## 1. Структура бота
- aiogram 3 dispatcher-архитектура: роутеры (`handlers/`) по фичам, middleware — общий.
- Один хендлер — одно действие. Сложная логика — в `services/`, хендлер только оркестрирует.
- Все хендлеры — **async**, блокирующие вызовы (requests, тяжёлый CPU) — через `asyncio.to_thread` или Celery.

## 2. Конфигурация и секреты
- Токен бота и ключи БД — только из окружения (`pydantic-settings`), в репо — только `.env.example`.
- `config.py` — один источник настроек, типизированный.

## 3. База данных
- SQLAlchemy 2.0 async + asyncpg; репозитории/DAO вместо裸 SQL в хендлерах.
- Сессии короткие, на запрос; `sessionmaker` через DI/middleware.
- Миграции — Alembic; изменение схемы = миграция.

## 4. FSM и состояние
- FSMState только для многошаговых сценариев; состояние в Redis (по умолчанию MemoryStorage не подходит для прода).
- Всегда очищай состояние (`state.clear()`) в конце сценария и на /cancel.

## 5. Клавиатуры и UX
- Инлайн-клавиатуры с `callback_data` в формате `<feature>:<action>:<id>`; парсинг — в роутере, не в тексте.
- Ответ на действия пользователя — в течение секунд; долгое — «⏳ считаю...» + фоновая задача.
- Тексты — в отдельном модуле (`texts.py`), не захардкожены в хендлерах.

## 6. Надёжность
- Обработка ошибок: глобальный middleware-обработчик исключений с логом и уведомлением админу.
- Устойчивость к флуду: rate limit на пользователя через Redis.
- Webhook для прода (asyncpg + aiohttp-web), polling — только для разработки.

## 7. Тесты
- Хендлеры тестируются через `aiogram` test utilities/FakeTelegram в unit-тестах; БД — через тестовую PostgreSQL (testcontainers) или транзакционные фикстуры.
- Каждый сценарий FSM — тест «сценарий пройден до конца» и «отмена посередине».
