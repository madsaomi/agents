# ✅ QA-чек-лист: Django + DRF (пресет django-drf)

## Перед каждым merge
- [ ] `pytest` — все тесты зелёные; новые тесты покрывают изменённую логику.
- [ ] `ruff check .` и `black --check .` — без замечаний.
- [ ] `python manage.py makemigrations --check --dry-run` — неожиданных миграций нет.
- [ ] Новые/изменённые модели имеют миграцию; миграция протестирована на копии данных (не только на пустой БД).
- [ ] Нет секретов в diff; `.env` не в индексе; `.env.example` обновлён при новых переменных.
- [ ] `select_related`/`prefetch_related` там, где были N+1 (проверь через `django-debug-toolbar`/`assertNumQueries`).
- [ ] Новые эндпоинты: разрешения явные, пагинация есть, ошибки в едином формате.
- [ ] `python agents/tools/check_integrity.py` — без ошибок.

## Безопасность (каждый релиз)
- [ ] CSRF/CORS — whitelist; `DEBUG=False` в prod-настройках.
- [ ] Загрузка файлов: валидация типа/размера, хранение вне веб-корня.
- [ ] SQL-инъекции: только ORM/параметризованные запросы.
- [ ] JWT: сроки access/refresh проверены, logout/ротация refresh протестированы.
- [ ] Права: аноним получает 401/403, чужие объекты — 404 (не утечка существования).

## Производительность (перед релизом на прод)
- [ ] Медленные запросы (< 200 мс на эндпоинте) — через `django-debug-toolbar`/`silk`.
- [ ] Долгие операции вынесены в Celery; задачи идемпотентны, retry настроен.
- [ ] Кэшируются дорогие вычисления с осмысленным TTL.
- [ ] Крупные выборки — пагинация или `.iterator()`.
