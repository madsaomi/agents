# 📏 Стандарты кодирования: Next.js (пресет nextjs)

> Стек: Next.js 15 (App Router) · TypeScript strict · Tailwind CSS

## 1. App Router
- `app/` — маршруты; серверные компоненты по умолчанию, `"use client"` — только там, где нужен state/event handlers.
- Server Actions для мутаций, `fetch` с `next: { revalidate }`/`cache` для чтения.
- Загрузка: `loading.tsx` + `error.tsx` для каждого значимого сегмента; параллельные данные — `Promise.all` в серверном компоненте или `<Suspense>`.

## 2. TypeScript
- `strict: true`; никаких `any` (кроме обоснованных `unknown` + narrow).
- Схемы API — zod; данные из БД/внешних API валидируются на границе.

## 3. Данные и безопасность
- Секреты — только `NEXT_PUBLIC_*` для клиентских (и минимум таких); приватные ключи — на сервере.
- Авторизация: middleware + проверка сессии на сервере; клиентские проверки — UX, не безопасность.
- Формы: server actions с валидацией zod, CSRF-защита через одноразовые токены/origin-check.

## 4. Производительность
- Изображения — `next/image`; тяжёлые библиотеки — `next/dynamic`.
- Не держать большие данные в client state — источник истины на сервере.
- Lighthouse: CLS/LCP в зелёной зоне для ключевых страниц.

## 5. Тесты
- Unit — Vitest (компоненты, утилиты, server actions); e2e — Playwright для критичных путей (логин, оплата, создание сущности).
- Каждая новая страница/действие — с тестом хотя бы happy path.
