## 1. 🎯 Цель и контекст

- **Проблема / Задача:** Записи памяти (планы, баги, ADR, сессии) связаны между собой только текстом: `см. agents/bugs_and_fixes/BUG_001...` — руками, без обнаружения битых связей и без обратных ссылок. Метаданных (теги) нет вообще — поиск только полнотекстовый, без фильтров «по домену/дате». Это последние крупные фичи «второго мозга» уровня Obsidian, которых не хватает.
- **Ожидаемый результат:** Вики-ссылки `[[BUG-001]]` между записями с проверкой разрешения и обратными ссылками (`brain.py links`); frontmatter-теги (`tags: [backend, auth]`) с фильтрами поиска (`--tag`, `--since`) и облаком тегов в `stats`.

## 4. 🛡️ Риски, сайд-эффекты и план отката

- **Ложные `[[...]]` в документации** (примеры в README/шаблонах) → неразрешёнными считаются только цели-идентификаторы (`[A-Za-z0-9_-]+` + опц. `.md`); `[[...]]`, `[[bug#1]]`-подобные с точками/спецсимволами — плейсхолдеры, молча пропускаются.
- **Миграция индекса** → авто-`ALTER TABLE`; при сбое — `search --reindex` (пересоздаёт).
- **Производительность** → `links` сканирует память на лету (десятки файлов, мс); фильтры поиска — пост-фильтр по уже отобранным кандидатам.
- **Откат:** `git revert` коммита этапа; БД-изменения обратимы `--reindex`.
