## 1. 🎯 Цель и контекст

- **Проблема / Задача:** Правила проекта сейчас — это markdown, который агент может проигнорировать. 5 дублей конфигов (CLAUDE.md, .cursorrules, .windsurfrules, copilot-instructions.md, second-brain.mdc) уже разошлись по содержанию. Нет тестов, ссылки `file:///` невалидны для GitHub/редакторов (но валидатор их искусственно принимает).
- **Ожидаемый результат:** Правила живут в одном месте (`agents/rules/`) и **исполняются**: генерируются конфиги (`brain.py sync`), принуждаются хуками Claude Code, подгружаются скиллами/субагентами, вызываются как функции через MCP. Плюс починенная база: относительные ссылки, тесты, CI.

**Порядок работ (утверждён заказчиком):** 1) база+тесты → 2) sync+хуки → 3) субагенты/skills/команды → 4) brain-mcp → 5) пресеты+пакет. Пункты 8–10 (поиск, мультиагентность, распространение) — этапами 6–7.

## 4. 🛡️ Риски, сайд-эффекты и план отката

1. **Форматы `.claude/` быстро меняются** → перед Этапами 2–4 сверка с официальной документацией (шаг 1.4); хуки держать в одном `settings.json`, скрипты — в `agents/tools/hooks/` (легко откатить: удалить `.claude/`).
2. **`mcp` SDK — сторонняя зависимость** против заявленного «stdlib-only» → только optional extra `[mcp]`; без него всё остальное работает. Альтернатива при конфликте: отложить Этап 4.
3. **Баг frontmatter `model:` у субагентов** (anthropics/claude-code#44385) → передавать модель явно при вызове; не полагаться на frontmatter до фикса.
4. **Синхронизированные файлы теряют ручную правку** → заголовок `GENERATED` + `sync --check` в CI; правило в ANTI_PATTERNS.
5. **Stop-хук может создавать дубли записей истории** → идемпотентность: проверка существования записи за текущую сессию/день.
6. **План отката:** каждый этап — отдельный коммит; `git revert` последнего коммита Этапа; хуки и sync изолированы от инструментов tools/.
